# B. 生成能力 Generative Competencies

> 學生必須透過整個 Capstone 歷程逐步形成並留下證據的核心能力。對應 `docs/key-tasks-breakdown.md` T1–T7 與 `docs/project-space-map-v1.md`。與 A 門檻能力區隔：此處能力無法前導速成，須在真實限制下實作並被驗證。

| 生成能力 | 對應任務 | 能力內涵 |
|---|---|---|
| **B1 跨角色需求轉譯與共識建構** | T1、T3 | 能在照服與護理語言、立場差異中，轉譯「何謂重要資訊／何謂已承接」，並與現場人員共識出可檢核的承接標準；證據：需求規格清單與 Gate 檢查表須經場域人員簽認 |
| **B2 資訊流診斷與斷點分析** | T2 | 能以證據（觀察、訪談、媒介比對）定位資訊在「觀察→回報→整合→處置→交接」鏈中的遺漏／重複確認時點，區分事實與臆測，並收斂至可介入的斷點假設；證據：斷點分析報告與一致性比對表 |
| **B3 限制下機制設計** | T3、T4 | 能在「節奏緊湊、跨班頻繁、資訊分散」不可移除的限制下，設計 L2 跨角色承接與確認機制（含誰／何時／對何資訊／如何確認／如何記錄），而非移除限制或設計單角色工具；證據：機制設計文件與操作流 |
| **B4 原型化與迭代** | T4、T5 | 能將機制轉為可操作的 Prototype（流程卡／表單／協作步驟等），進行低風險試跑並依回饋快速迭代，記錄迭代決策依據；證據：Prototype 版本對照與迭代紀錄 |
| **B5 場域驗證與證據評估** | T5、T6 | 能設計並執行場域驗證（含常態與尖峰切片），蒐集「下一班是否已承接／需延續」證據，評估機制對遺漏／重複確認的改善與未解問題；證據：場域驗證報告與前後比對 |
| **B6 協作與反思移轉** | T3、T6、T7 | 能在跨角色、跨班協作中協調分工、處理確認分歧，並將機制與操作指引移轉給場域，進行系統性反思與證據鏈總結；證據：移轉文件、反思紀錄與成果發表 |

> **與門檻能力差異**：A 能力為「進場前就能做」，B 能力為「在限制下做出可驗證的機制並留下證據」；B 能力須通過 T2→T6 的真實場域證據檢核，非課堂練習可替代。
