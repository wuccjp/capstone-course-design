# Gate 設定｜品質與方向判斷的關鍵決策點

> 16 週僅設 2 個 Gate，非每 Milestone 皆設。Gate 代表「若此處判斷錯誤，後面專題方向將整體偏掉」。來源 `docs/milestones.md` M1–M4。

| Gate | 設置位置 | 核心判斷 | 主要檢核問題 | Gate Decision |
|---|---|---|---|---|
| **G1 診斷與定錨 Gate** | **W09 M2** 之後<br>（P3→P4 結束，進入 P5 設計前） | 診斷是否正確且定錨是否位於 Challenge Boundary 內，是否值得進入設計 | 1. 斷點是否以場域證據（觀察／訪談／媒介比對）為依據，而非臆測？<br>2. 是否鎖定 L2 資訊流與交接層（非 L1/L3），聚焦照服↔護理跨角色？<br>3. 是否涵蓋「觀察回報→護理整合處置→下一班交接」情境，而非片段？<br>4. 需求是否轉為 4 檢核（承接／整合／確認／延續）且獲場域人員共識？<br>5. 是否正視三限制（緊湊／頻繁／分散）而非試圖移除？ | **Go**：通過，進入 P5 設計<br>**Conditional Go**：小幅修正斷點或邊界後進入<br>**Recycle**：證據不足，退回 P2 補蒐集<br>**Re-anchor**：方向偏離，重新定錨 PS-A/B/C/D |

## 為何僅 2 個 Gate

- **M1（W05 證據建構）不設 Gate**：證據薄弱可透過形成性回饋在 W06 補強，未到方向偏掉臨界點，設為 Checkpoint 即可。
- **M4（W16 驗證與整合）不設 Gate**：為終點成果評量，非決策分岔點；G1 與 G2 已確保方向，M4 僅做品質評分。

> 兩 Gate 皆需留下 Learning Evidence（G1：斷點報告＋簽認需求清單；G2：Prototype＋試跑紀錄），未通過者不得進入下一階段，對應 `docs/course-schedule-16w.md`。
