# 關鍵任務拆解 — 從 Challenge 到學生必須完成的工作

> 原則：先定義「必須完成的工作」，知識為完成任務而學。對應 Challenge：L2 照服↔護理、住民重要變化後「觀察回報→護理整合處置→下一班交接」、限制（節奏緊湊／跨班頻繁／資訊分散）、需求（即時清楚承接整合確認延續）｜來源 `docs/challenge-boundary.md:57` & `docs/project-space-map-v1.md:5`

| 關鍵任務 | 學生需要完成的具體工作 | 任務產出 |
|---|---|---|
| **T1 場域進場與現況描繪** | 進入照護場域，跟隨照服與護理各至少 2 班，實地觀察「觀察→回報→整合→處置→交接」全鏈；訪談兩角色對「何謂重要變化」與「何謂已承接」的認知；盤點實際使用的資訊媒介與交接形式；繪製現況流程圖 | 現況流程圖（As-Is）、訪談紀錄、媒介與交接形式盤點表 |
| **T2 斷點診斷與證據收斂** | 比對觀察紀錄與實際交班資訊，標定遺漏／重複確認的發生時點與樣態；分析媒介分散導致的不一致；彙整 R1-R5/S1-S4/P1-P4/I2/C1-C3 的田野證據，收斂至 PS-A/B/C/D 之一的具體斷點假設；標示需場域驗證處 | 斷點分析報告、資訊一致性比對表、優先探究問題假設（對應 Project Space） |
| **T3 跨角色需求定義與介入邊界收斂** | 與場域人員共識「重要資訊必須被承接的樣態」：何謂即時／清楚／已確認；定義可介入的 L2 範圍與不可碰觸邊界（排除 L1/L3）；將需求轉為機制必須滿足的檢核條件（承接、整合、確認、延續四項） | 需求規格清單（四項檢核條件）、介入邊界說明、Gate 檢查表（對應 04 定錨） |
| **T4 承接與確認機制原型設計** | 依所選 Space（A 前端轉譯／B 中段整合／C 後段延續／D 情境負荷）設計「跨角色承接與確認」的運作機制與操作流（含誰在何時、對什麼資訊、如何確認、如何記錄）；製作可操作的原型（表單／流程卡／協作步驟等，非指特定 App／AI／平台）；撰寫操作指引與預期驗證指標 | 機制原型（Prototype）、操作指引、驗證計畫（含指標與方法草案） |
| **T5 內部測試與迭代** | 在模擬或低風險時段進行內部試跑，邀請照服／護理實際走一次機制；記錄操作耗時、遺漏／重複是否改善、協調行為是否被省略；依回饋快速迭代 1–2 輪 | 試跑紀錄、測試報告、迭代版本對照表 |
| **T6 場域驗證** | 在真實「住民重要變化後到下一班交接」情境中實地驗證，包含常態與尖峰（或夜班）情境切片；蒐集下一班是否已承接／需延續的證據；比對驗證前後資訊遺漏／重複確認變化；記錄限制（緊湊／頻繁／分散）是否仍被正視而非被移除 | 場域驗證報告、交接完成度比對、限制正視檢核 |
| **T7 成果總結與移轉** | 整理機制成效、未解決斷點與後續追蹤建議；將機制與操作指引移轉給場域人員；進行成果發表與反思，說明探索→診斷→介入→設計→驗證的證據鏈 | 成果發表簡報、結案報告（含移轉文件）、反思紀錄 |

> **對應課程流程**：T1→01 問題探索｜T2→02 問題診斷｜T3→03 介入判斷＋04 小組專題定錨｜T4→05 解方設計｜T5→06 Prototype｜T6→07 場域驗證｜T7→總結。知識（訪談法、流程圖、資訊分析、協作設計、原型測試、驗證方法）皆為完成 T1–T7 而學，非先授知識再做任務。
