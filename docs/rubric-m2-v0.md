# 從 CO2 × Evidence 推導 Assessment Criteria

> CO2 問題診斷（對應 `docs/competency-co-objectives.md` CO1 科學實證之診斷面向、矩陣 CO2）。依 `docs/learning-evidence-map.md` M2 證據（斷點報告、需求清單、Gate 檢查表）推導。

| 評量向度 | 主要判斷內容 |
|---|---|
| **A｜場域證據運用** | 問題分析是否建立在具體、可追溯的訪談、觀察及場域證據上 |
| **B｜問題現象辨識** | 是否能辨識角色工作痛點、流程卡點及資訊斷點，而非停留在抽象問題標籤 |
| **C｜跨面向關聯分析** | 是否能建立 Journey、Process、Information Flow 及跨角色問題之間有證據支持的關係 |
| **D｜核心問題形成** | 是否能從多項現象與關係形成具系統性、重要性且值得介入的 Core Problem |
| **E｜證據與推論邊界** | 是否能區分已知證據、合理推論與待驗證假設，避免將推測視為事實 |

# Rubric V0｜M2 問題診斷與核心問題

> Milestone M2 W09（G1 Gate），證據：斷點分析報告＋簽認需求清單＋Gate 檢查表。R1 待加強、R2 基本、R3 良好、R4 優異。

| 評量向度 | R1 待加強 | R2 基本 | R3 良好 | R4 優異 |
|---|---|---|---|---|
| **A 場域證據運用** | 無具體證據或證據不可追溯（無訪談原話、觀察紀錄或媒介比對）；問題描述為個人臆測 | 有 1 類證據（僅訪談或僅觀察），部分可追溯，但缺多源比對 | 有 2–3 類證據（訪談＋觀察＋媒介比對），多數可追溯，能標示證據來源與時間 | 3 類證據完整且可追溯，建立證據索引表，能以三角比對互相驗證並標示侷限 |
| **B 問題現象辨識** | 僅用抽象標籤（「溝通不良」「效率差」），未指明人／時／事 | 能列出現象但描述模糊，未區分角色痛點、流程卡點與資訊斷點 | 能具體辨識至少 2 類痛點：角色工作痛點、流程卡點、資訊斷點，並有事例佐證 | 能精準定位痛點／卡點／斷點在「觀察→回報→整合→交接」鏈的具體節點，並量化或質性說明頻次與影響 |
| **C 跨面向關聯分析** | 現象孤立呈現，無關聯 | 能建立單一面向關聯（如僅流程），但缺乏 Journey／Information Flow 或跨角色視角 | 能建立 Journey、Process、Information Flow 與跨角色至少 2 個面向的有據關聯，並以證據說明因果或連動 | 能建立 4 面向完整關聯網路，以證據支撐「為何此斷點在彼情境、由此角色、經此資訊流產生」，並能反駁替代解釋 |
| **D 核心問題形成** | 無 Core Problem 或問題過大過泛 | 能提出 Core Problem 但系統性或重要性不足，介入價值模糊 | 能從多現象與關聯形成具系統性、重要性且值得介入的 Core Problem，並對應 PS-A/B/C/D 範圍與 L2 邊界 | Core Problem 具系統性、重要性、介入可行性三者兼具，能清楚說明「為何此時、以此角色、在此段介入最具槓桿」，並獲場域共識 |
| **E 證據與推論邊界** | 將推測視為事實，未區分已驗證與待驗證 | 能區分部分證據與推論，但仍有混淆，待驗證假設未標示 | 能明確區分已知證據、合理推論與待驗證假設，並標示需場域驗證處，未將推測當事實 | 能完整標示證據→推論→假設的邊界，明確列出「需場域驗證」清單，並說明驗證方法與風險，避免過度推論 |

> **Gate 門檻**：G1 通過需 A–E 皆達 R2 以上，且 A 與 D 不得為 R1；R3 以上始得 Conditional Go 進入 P5，R4 為標竿。
