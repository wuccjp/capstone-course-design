# L2 Prototype 原型規格

## 原型目標
驗證「30秒發卡 → 5分鐘簽收 → 交班一鍵清單」是否在緊湊場域中可行且減少遺漏。

## 原型形式：三階段漸進

### P0 紙本+表單原型（1週可測）
- **工具**：Google 表單（照服發卡）+ Google Sheet 看板（護理整合）+ 列印卡片
- **欄位**：對應承接卡 9 欄位
- **看板**：Sheet 四欄看板（待確認/已處置/待交接/已結案）+ 條件式上色
- **推播**：表單提交自動發 LINE Notify 到護理群（附 Sheet 連結）
- **交接**：Sheet 篩選「待交接」列印為交班清單

### P1 輕量 Web 原型（2-3週）
- **前端**：單頁 Web（手機友善），語音輸入、掃床號 QR Code
- **後端**：Firebase/Supabase，狀態機驅動
- **功能**：發卡、簽收、處置回填、交接清單生成、逾時紅燈
- **整合**：LINE Bot 推播

### P2 場域整合原型（4週+）
- 與現有照護系統串接，住民資料自動帶入

## 操作流程腳本（測試用）

**角色**：照服 A、護理 B、下一班照服 C

1. A 發現 301 奶奶午餐只吃1/3 → 30秒內用手機發卡（🟡）
2. B 收到推播 → 2分鐘內簽收 → 訪視後填「已量體溫、下一餐追蹤」
3. 系統通知 A「已處置」
4. 15:00 交班 → C 登入看板 → 列印「待交接」1 筆 → 口頭確認簽收
5. 晚餐後 C 回填「晚餐吃2/3」→ 結案

## 成功指標（對應場域驗證）

- 發卡平均時間 < 60 秒
- 簽收率 100%（10分鐘內）
- 交班遺漏率 < 5%（對照現況口頭交班）
- 照服/護理主觀負擔不增加（問卷）

## 風險與備案

- 擔心手機使用不便 → 紙本卡片備用，護理代為建卡
- 擔心多一系統 → 強調取代 LINE 洗版，非額外負擔
