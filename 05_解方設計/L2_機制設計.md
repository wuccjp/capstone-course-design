# L2 解方設計：跨角色照護資訊承接與確認機制

## 一、機制總覽：三階承接 + 一板一眼

```
[照服現場] --(30秒回報卡)--> [護理整合板] --(處置回饋)--> [跨班交接清單]
     |                           |                          |
   產生端                      整合端                     延續端
```

**核心物件**：一張「重要變化承接卡」貫穿全程，狀態驅動流轉。

## 二、資訊物件設計：承接卡（Handover Card）

| 欄位 | 類型 | 說明 | 範例 |
|------|------|------|------|
| 住民 | 選單 | 床號/姓名 | 301 陳奶奶 |
| 變化類別 | 單選 | 生命徵象/進食/排泄/情緒行為/傷口/跌倒/其他 | 進食 |
| 發現時間 | 自動 | 系統時間戳 | 02/15 14:20 |
| 回報人 | 自動 | 登入者 | 照服 王OO |
| 具體觀察 | 勾選+簡述 | 結構化勾選 + 一句話 | 午餐只吃1/3、精神較差 |
| 緊急度 | 三級 | 🔴立即/🟡今日內/🟢持續觀察 | 🟡 |
| 狀態 | 自動 | 待確認/已處置/待交接/已結案 | 待確認 |
| 護理處置 | 護理填 | 處置內容+追蹤指示 | 已量體溫37.8，下一餐追蹤進食 |
| 確認簽收 | 簽名 | 護理/下一班簽收 | 護理 李OO 14:35 |

**設計要點**：照服只需填前6欄（勾選為主），護理補後3欄。

## 三、流程設計（服務藍圖）

### 流程1：即時承接（0-5分鐘）
1. 照服發現變化 → 手機/平板 30秒發卡（或語音轉卡）
2. 護理站看板即時亮點 + 推播（🔴立即震動）
3. 護理 5 分鐘內「簽收」→ 狀態變「已確認」

### 流程2：整合處置（5-60分鐘）
4. 護理評估處置 → 填寫「護理處置」欄
5. 系統自動推播回饋給「回報照服」→ 形成閉環
6. 狀態變「待交接」並自動加入交接清單

### 流程3：跨班延續（交班時）
7. 下一班照服/護理接班 → 系統一鍵列印/投影「待延續清單」（依住民/緊急度排序）
8. 交班時逐條口頭確認 → 接收方「簽收」
9. 執行後回填結果 → 狀態「已結案」或持續追蹤

## 四、載具設計：輕量整合看板

- **不新增系統**：以現有 LINE/紙本為過渡，優先用 **共享看板（Google Sheet/Notion/簡易Web）** 作為單一真相源
- **實體輔助**：護理站白板對應「待確認/待交接」兩欄，卡片列印夾板
- **關鍵規則**：
  - 重要變化一律發卡，不用 LINE 口頭
  - LINE 僅發「已發卡通知」連結，不洗版
  - 交班本只抄「待延續」清單，不重抄全部

## 五、確認機制（防漏接）

| 機制 | 說明 |
|------|------|
| 簽收制 | 每張卡需護理簽收，未簽收 10 分鐘紅燈提醒 |
| 回饋制 | 護理處置後自動通知回報人 |
| 清單制 | 交班清單需逐條勾選簽收，未勾選無法完成交班 |
| 追蹤制 | 已結案需填結果，否則 24hr 後重提提醒 |

## 六、與限制的對應

- 節奏緊湊 → 30秒勾選卡 + 語音轉文字
- 跨班頻繁 → 自動生成待延續清單，不靠記憶
- 資訊分散 → 單一卡片流，LINE/紙本僅為通知與備份
- 遺漏/重複 → 簽收+狀態燈號，清楚誰未接、誰已接

## 七、不做什麼（Scope 界定）

- 不做完整電子病歷，僅聚焦「重要變化」此一資訊流
- 不取代護理專業判斷，僅協助承接與確認
- 不要求即時全員上線，離線可紙卡暫代，事後補卡
